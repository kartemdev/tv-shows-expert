# Backlog TV Shows Expert

## Цель и исходное состояние

Довести приложение до сценария из [README](README.md): найти сериал по названию, отфильтровать результаты по жанру, посмотреть описание и рейтинг. Подготовить минимальную дизайн-систему по предоставленному макету, инфраструктуру работы с API и хранить общее состояние поиска в React Context.

На момент составления backlog в проекте настроены React, TypeScript, Vite, Biome и проверка лимита строк. `MainPage` выводит `Hello World!`; поиск, карточки и фильтры ещё не реализованы. Тестового раннера нет.

Объём взят из README, текущего кода и уточнений к backlog: минимальная дизайн-система, инфраструктура API и React Context включены в работу; сезоны, серии и их статистика пока исключены. Рабочие допущения ниже уточняют README; сценарий переноса формы и сохранения режима страницы задан пользователем 10 ноября 2026 года и обязателен для реализации. Структура обновлена по уточнению от 11 ноября: компоненты интерфейса — в `src/components/`, запросы и DTO — в `src/api/`, сущность сериала, маппер и общее состояние — в `src/model/`.

## Рабочие допущения

- Поиск запускается отправкой формы: кнопкой «Искать» или Enter. Ввод и очистка не создают запросов; автопоиска и debounce нет. Пустой или пробельный текст не запускает поиск и не меняет режим страницы.
- До первой принятой отправки форма находится в расширенном hero. При первой отправке непустого запроса hero сужается, форма в нём скрывается, единственная форма появляется над карточками и к ней выполняется однократная прокрутка, не дожидаясь ответа API.
- После этого форма остаётся у карточек при очистке поля, новом поиске, пустом ответе и ошибке. Очистка меняет только текст поля: выдача, последний запрос, статус, ошибка и жанр сохраняются; активный запрос не отменяется. К расширенному hero с формой возвращаемся только после перезагрузки страницы.
- Фильтрация локальная: один выбранный жанр либо «Все жанры». Фильтр применяется только к результатам текущего поиска.
- Пагинация локальная, после фильтрации по жанру: по 6 сериалов на страницу. В Context хранится номер страницы, срез выдачи и число страниц вычисляются из исходных данных. Новый принятый поиск, выбор и сброс жанра возвращают страницу 1; ввод и очистка поля сохраняют текущую страницу. Переключение страниц не создаёт запросов.
- Информация о сериале находится в карточке.
- Интерфейс на русском; названия, жанры и описания из API показываются на языке источника.
- Инфраструктура API строится на `fetch`: общий HTTP-клиент отделён от методов TVMaze и состояния React.
- API использует `shared`, но не импортирует `model`, компоненты или страницы. Метод поиска проверяет DTO и принимает маппер параметром; `searchedShowMapper` в модели преобразует DTO в `SearchedShow`.
- Общее состояние поиска, Context, reducer и специализированные хуки хранятся в `src/model/searchedShow/`. Provider подключается страницей выше компонентов поиска и выдачи и управляет состоянием через `useReducer`; Presenter читает состояние и вызывает действия через хуки модели. Краткоживущее состояние отдельной карточки, например ошибка постера, остаётся локальным.
- Начальный поиск (`InitialSearch`), поиск у карточек (`ResultsSearch`), экран карточек (`ShowsScreen`) и жанровые кнопки (`GenreTabs`) — отдельные компоненты в `src/components/`. Обе формы используют одну модель; одновременно в DOM и Tab-порядке присутствует только форма текущего режима.
- Context хранит состояние в памяти на время жизни Provider; он не размонтируется при переносе формы и сжатии hero. Перезагрузка создаёт начальное состояние с расширенным hero и пустой формой; хранения в URL или браузерных хранилищах нет. Новые зависимости добавляются только при обоснованной необходимости конкретного PR.

Визуальный референс — предоставленный файл `Поиск сериалов по жанрам (3).make`. Экспорт от 10 ноября 2026 года; просмотрены его превью и исходные стили и разметка. В макете есть тёмный первый экран, светлая область результатов, золотистый акцент, крупный заголовок с курсивным выделением, поисковая строка, чипы жанров и сетка карточек.

Значения из макета — отправная точка: при подготовке системы проверить контраст, читаемость мелкого текста и управление с клавиатуры. Недостающие состояния оформить в том же визуальном языке. Анимации учитывать вместе с `prefers-reduced-motion`.

Минимальная система состоит из токенов, базовых стилей и короткой спецификации элементов. Единый стиль применяется и к обычным HTML-элементам внутри локального компонента; отдельная React-обёртка нужна, когда у неё есть собственная ответственность.

### Размещение стилей и компонентов

- Общие токены и базовые стили размещаются в `src/shared/styles/`, а стили конкретного элемента — рядом с его компонентом-владельцем.
- Поле поиска и его кнопка принадлежат соответствующей форме в `InitialSearch` или `ResultsSearch`, жанровые кнопки — `GenreTabs`, карточка — `ShowsScreen/ShowCard`. `MainPage` связывает расширенный / компактный hero и текущий компонент формы по данным модели; панель поиска не зависит от наличия карточек. Выделение дочернего компонента по сложности сохраняет его внутри владельца.
- Когда элемент нужен нескольким потомкам одной ветки, он размещается в `components` ближайшего общего владельца. В `src/shared/components` компонент поднимается при использовании разными страницами или самостоятельными ветками. Для каждого такого переноса в PR указываются реальные потребители.

Элементы избранного и сведения о сезонах, присутствующие в макете, остаются за границей текущего объёма. Пагинация возвращена в backlog отдельным PR-07 по уточнению от 13 ноября 2026 года; её поведение не входит в PR-02–06. Поведение поиска определяется задачами ниже; демонстрационные данные и логика прототипа служат только контекстом для дизайна.

## PR-02. Инфраструктура API

**Результат:** есть единая точка выполнения HTTP-запросов и типизированный метод поиска TVMaze, независимые от React и способа хранения состояния.

Адрес API задаётся в одном месте; сетевой клиент не содержит UI-состояния и бизнес-правил фильтрации. API не импортирует модель и получает маппер параметром.
