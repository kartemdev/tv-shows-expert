# Backlog TV Shows Expert

## Цель и исходное состояние

Довести приложение до сценария из [README](README.md): найти сериал по названию, отфильтровать результаты по жанру, посмотреть описание и рейтинг. Подготовить минимальную дизайн-систему по предоставленному макету, инфраструктуру работы с API и хранить общее состояние поиска в React Context.

На момент составления backlog в проекте настроены React, TypeScript, Vite, Biome и проверка лимита строк. `MainPage` выводит `Hello World!`; поиск, карточки и фильтры ещё не реализованы. Тестового раннера нет.

Объём взят из README, текущего кода и уточнений к backlog: минимальная дизайн-система, инфраструктура API и React Context включены в работу; сезоны, серии и их статистика пока исключены. Рабочие допущения ниже уточняют README; сценарий переноса формы и сохранения режима страницы задан пользователем 10 ноября 2026 года и обязателен для реализации.

## Рабочие допущения

- Поиск запускается отправкой формы: кнопкой «Искать» или Enter. Ввод и очистка не создают запросов; автопоиска и debounce нет. Пустой или пробельный текст не запускает поиск и не меняет режим страницы.
- До первой принятой отправки форма находится в расширенном hero. При первой отправке непустого запроса hero сужается, форма в нём скрывается, единственная форма появляется над карточками и к ней выполняется однократная прокрутка, не дожидаясь ответа API.
- После этого форма остаётся у карточек при очистке поля, новом поиске, пустом ответе и ошибке. Очистка меняет только текст поля: выдача, последний запрос, статус, ошибка и жанр сохраняются; активный запрос не отменяется. К расширенному hero с формой возвращаемся только после перезагрузки страницы.
- Фильтрация локальная: один выбранный жанр либо «Все жанры». Фильтр применяется только к результатам текущего поиска.
- Информация о сериале находится в карточке.
- Интерфейс на русском; названия, жанры и описания из API показываются на языке источника.
- Инфраструктура API строится на `fetch`: общий HTTP-клиент отделён от методов TVMaze и состояния React.
- Общее состояние поиска хранится в React Context на границе фичи. Provider управляет состоянием через `useReducer`; Presenter читает состояние и вызывает действия через специализированные хуки. Краткоживущее состояние отдельной карточки, например ошибка постера, остаётся локальным.
- Context хранит состояние в памяти на время жизни Provider; он не размонтируется при переносе формы и сжатии hero. Перезагрузка создаёт начальное состояние с расширенным hero и пустой формой; хранения в URL или браузерных хранилищах нет. Новые зависимости добавляются только при обоснованной необходимости конкретного PR.

## Дизайн и минимальная дизайн-система

Визуальный референс — предоставленный файл `Поиск сериалов по жанрам (3).make`. Экспорт от 10 ноября 2026 года; просмотрены его превью и исходные стили и разметка. В макете есть тёмный первый экран, светлая область результатов, золотистый акцент, крупный заголовок с курсивным выделением, поисковая строка, чипы жанров и сетка карточек.

Тексты первого экрана: «Сериал на вечер? Мы поможем найти.» и «Тщательно отобранные истории для любого настроения». Актуальная спецификация, референсы и пользовательские поправки к поведению финального макета — в [docs/design.md](docs/design.md#переход-к-результатам). Исходные автопоиск, сброс при очистке и дублирование поля из `.make (3)` заменяются контрактом выше.

Значения из макета — отправная точка: при подготовке системы проверить контраст, читаемость мелкого текста и управление с клавиатуры. Недостающие состояния оформить в том же визуальном языке. Анимации учитывать вместе с `prefers-reduced-motion`.

Минимальная система состоит из токенов, базовых стилей и короткой спецификации элементов. Единый стиль применяется и к обычным HTML-элементам внутри локального компонента; отдельная React-обёртка нужна, когда у неё есть собственная ответственность.

### Размещение стилей и компонентов

- Общие токены и базовые стили размещаются в `src/shared/styles/`, а стили конкретного элемента — рядом с его компонентом-владельцем.
- Поле поиска и его кнопка принадлежат `SearchForm` в ветке `ShowSearch`, чип жанра — `GenreFilter`, карточка — `SearchResults`. `ShowSearch` связывает расширенный / компактный hero и положение единственной формы; панель поиска не зависит от наличия карточек. Выделение дочернего компонента по сложности сохраняет его внутри владельца.
- Когда элемент нужен нескольким потребителям одной фичи, он размещается в `components` ближайшей общей ветки. Например, одинаковая кнопка поиска и повтора может принадлежать `ShowSearch/components`, если действительно используется в обеих ветках.
- В `src/shared/components` компонент поднимается при использовании разными страницами или независимыми фичами. Для каждого такого переноса в PR указываются реальные потребители.

Элементы избранного, пагинация и сведения о сезонах, присутствующие в макете, остаются за границей текущего объёма. Поведение поиска определяется задачами ниже; демонстрационные данные и логика прототипа служат только контекстом для дизайна.

## Общие условия готовности PR

- Выполнены критерии приёмки задачи; в описании PR указаны результат и проверенные сценарии.
- Соблюдён [архитектурный документ](docs/architecture.md): у каждого View собственный Presenter, логика вне JSX, дочерние компоненты внутри владельца, переиспользование на уровне ближайшей общей ветки.

- Пока нет тестового раннера, сценарии ниже проверяются вручную, при необходимости с подменой ответов API. Сборка и проверка типов не заменяют проверку поведения и архитектуры.

## PR-03. Состояние поиска в React Context

**Результат:** состояние и действия поиска доступны потребителям одной ветки через Context; жизненным циклом запросов управляет Provider.

**Область:** `src/features/showSearch/ShowSearch/`: определение Context, reducer, специализированные хуки и компонент `ShowSearchProvider` с собственным Presenter. Provider подключается на границе ветки поиска. Вспомогательная логика запросов выделяется из Presenter по ответственности.

**Задачи:**

- [ ] Описать типизированное состояние: редактируемый запрос, последний отправленный запрос, исходная выдача, статус `idle / loading / success / error`, ошибка и флаг `hasSubmittedSearch` (изначально false). Выбранный жанр добавляется в PR-06.
- [ ] Реализовать reducer с явными переходами и начальным состоянием; общее состояние не дублировать в локальных хуках потребителей.
- [ ] Предоставить хуки чтения состояния и действий: изменение поля, запуск поиска и повтор последнего отправленного запроса. Использование вне Provider должно давать понятную ошибку разработчику.
- [ ] Связать действия с методом API из PR-02: обрезать пробелы при отправке, игнорировать пустой запрос, устанавливать `hasSubmittedSearch` в true при первой принятой отправке до ответа API, очищать старую выдачу при новом поиске, сохранять ошибку и результат в Context. Изменение поля, включая очистку, меняет только текст и не запускает запрос.
- [ ] Сохранять `hasSubmittedSearch` независимо от текста, статуса API и наличия результатов. Перенос формы и сжатие hero не размонтируют Provider; флаг не сбрасывается при редактировании, очистке, повторе и ошибке.
- [ ] Отменять предыдущий запрос при новом поиске и при размонтировании Provider; защищать состояние от запоздалых ответов. Контроллер отмены и идентификатор активного запроса хранить в служебных refs, а не в отображаемом состоянии.

**Критерии приёмки:**

- [ ] Несколько потребителей одного Provider видят согласованные запрос, статус и выдачу; изменение состояния не требует передачи их через промежуточные компоненты.
- [ ] Проверены переходы `idle → loading → success`, `loading → error` и повтор после ошибки на контролируемых ответах API.
- [ ] Если ответ A пришёл после ответа на более новый запрос B, выдача B остаётся в Context. Отмена не переводит состояние в `error`.
- [ ] Изменение и полная очистка поля без отправки сохраняют выдачу, последний отправленный запрос, статус, ошибку и флаг режима, не отменяют активный запрос. Повтор использует последний отправленный запрос, даже если поле пустое.
- [ ] Первая отправка непустого текста переводит `hasSubmittedSearch` false → true сразу при loading; пустая отправка не меняет флаг. Пустой результат и ошибка сохраняют true; ввод до первой отправки сохраняет false.
- [ ] Перерисовка потребителя сама по себе не создаёт запрос; после размонтирования Provider запрос отменён, при новом монтировании состояние начальное.
- [ ] Исходная выдача хранится единожды; отфильтрованные результаты и список жанров позднее вычисляются из неё. Выполнены общие условия готовности PR.

## PR-04. Поиск сериалов через TVMaze

**Результат:** пользователь вводит название и получает список найденных сериалов.

**Область:** существующий `src/features/showSearch/ShowSearch/` с собственными `SearchForm`, `SearchResults` и `SearchResults/ShowCard`. Presenter компонентов используют хуки Context из PR-03 и модели фичи из PR-02.

**Задачи:**

- [ ] Добавить одну форму с подписанным полем и кнопкой «Искать»; связать значение и отправку с действиями Context через Presenter формы. Кнопка и Enter запускают один сценарий; автопоиска при вводе и debounce нет.
- [ ] До первого поиска разместить форму в расширенном hero. При первой принятой отправке по `hasSubmittedSearch` сжать hero, скрыть форму в нём и разместить ту же форму с сохранённым текстом и кнопкой «Искать» в закреплённой панели над карточками. Одновременно доступна только одна форма.
- [ ] После смены компоновки однократно прокрутить к панели поиска, не дожидаясь ответа API: smooth в обычном режиме, auto при reduced motion. При клавиатурной отправке перенести фокус из скрываемой формы в поле новой позиции без дополнительной прокрутки.
- [ ] Оформить область выдачи на светлой поверхности с заголовком и количеством результатов. Панель с формой сохраняется при загрузке, ошибке, пустой выдаче, редактировании и очистке поля. Состояния и оба положения формы соответствуют PR-00.
- [ ] Показать начальную подсказку, загрузку, список, отсутствие результатов и ошибку с повтором по состоянию Context. Подготовить пользовательские сообщения в Presenter или его помощниках.
- [ ] Связать повтор с действием из PR-03; не создавать вторую реализацию запросов или локальную копию выдачи в компоненте.
- [ ] Добавить минимальный `ShowCard`: название и ссылка на страницу сериала в TVMaze. Сохранять порядок API и использовать ID сериала как ключ.

- [ ] Кнопка «Искать» и Enter запускают одинаковый поиск в обеих позициях формы; ввод и очистка не создают запросов. Пустая строка и строка из пробелов не отправляются и не меняют режим страницы.
- [ ] При первой отправке непустого запроса hero становится компактным и форма появляется у карточек уже при loading, с однократной прокруткой. После ответа, ошибки и последующих отправок переход и автоскролл не повторяются.
- [ ] До первой отправки в DOM и Tab-порядке доступна только форма в hero; после неё — только форма в панели выдачи. Клавиатурный фокус не теряется при переносе, панель доступна на 360/768/1280 px и не перекрывает содержимое.
- [ ] Пробелы, `&` и другие специальные символы передаются как часть названия.
- [ ] Успешный ответ отображается списком, пустой массив — сообщением «Ничего не найдено».
- [ ] Ошибка сети, HTTP 429 или 5xx показывается понятным сообщением; повтор использует последний отправленный запрос. Автоматического бесконечного повтора нет.
- [ ] Если ответ на запрос A пришёл после ответа на более новый запрос B, выдача B остаётся на экране. Отмена не показывается как ошибка.
- [ ] После успешного поиска полностью очистить поле: текст пустой, hero компактен, форма у карточек, выдача, счётчик и последний запрос сохранены; запросов и прокрутки нет. Повторить очистку при loading и error: статус не сбрасывается, запрос не отменяется, повтор использует последний отправленный текст.
- [ ] Перезагрузка после поиска или очистки возвращает расширенный hero с пустой формой и начальным состоянием; внутренний переход к началу страницы этого не делает. Загрузка и результат объявляются средствами доступности.
- [ ] Выполнены общие условия готовности PR.

## PR-06. Фильтрация по жанру

**Результат:** пользователь сужает текущую выдачу до сериалов выбранного жанра и может вернуться ко всем результатам.

**Область:** `ShowSearch/GenreFilter/` и Context из PR-03. Выбранный жанр хранится вместе с общим состоянием поиска; Presenter готовят данные для фильтра и результатов через специализированные хуки.

**Задачи:**

- [ ] Получать уникальный отсортированный список жанров из полной успешной выдачи текущего поиска.
- [ ] Добавить выбранный жанр в состояние Context и действия выбора и сброса в reducer. Список жанров и отфильтрованную выдачу вычислять из исходных данных, не хранить отдельными копиями.
- [ ] Добавить выбор одного жанра в виде группы кнопок-чипов по макету, с вариантом «Все жанры» и возможностью сброса. Подготовить `aria-pressed`, доступное название группы и видимый фокус; выбранное состояние различимо помимо цвета.
- [ ] Обеспечить доступность всех жанров при переполнении на узком экране согласно правилам PR-00.
- [ ] Подготовить отфильтрованные элементы и количество видимых результатов вне View, сохранив исходный массив и порядок API.
- [ ] В переходе reducer к новому поиску сбрасывать фильтр. Не менять жанр при простом редактировании поля поиска.
- [ ] Разделить отсутствие результатов поиска и отсутствие совпадений фильтра. Во втором состоянии оставить доступным сброс.

**Критерии приёмки:**

- [ ] Сериалы без жанров видны при выборе «Все жанры»; если жанров нет во всей выдаче, фильтр недоступен или скрыт с понятным пояснением.
- [ ] Состояние без совпадений и сброс проверены на контролируемых данных; новый поиск не наследует старый выбор жанра.
- [ ] Выполнены общие условия готовности PR.
