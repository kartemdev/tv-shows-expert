# Работа с TV Shows Expert

Учебное приложение на React и TypeScript: поиск сериалов через TVMaze, фильтрация по жанрам и карточки результатов.

## Источники правил

- [README.md](README.md) — назначение проекта, структура, стек и запуск.
- [docs/architecture.md](docs/architecture.md) — источник архитектурных правил. Читай его перед изменением React-кода; не заменяй правила привычными соглашениями других архитектур.
- [docs/design.md](docs/design.md) — поведение интерфейса, состояния и адаптация; читай нужные разделы при изменении UI.
- `package.json`, `tsconfig.json`, `biome.json` — актуальные команды и настройки инструментов.

Архитектурный документ меняй только по запросу на изменение самой архитектуры. UI сценария размещай в `src/components/`, HTTP-методы и DTO — в `src/api/`, сущности, мапперы, Zustand-хранилища и правила изменения данных — в `src/model/`. API может использовать `shared`, но не импортирует модель, задачи, компоненты и страницы. Дорабатывай нужный слой и ветку компонентов. Переносы и новые зависимости должны быть нужны для задачи.

Маппер принадлежит модели и передаётся в метод API параметром. Presenter подписывается через селекторы модели на нужное состояние и использует её публичные операции. Сценарии приложения оформляй как `tasks` по правилам архитектурного документа и вызывай их из Presenter.

Размещай сценарии, используемые независимыми ветками приложения, в `src/tasks/`. Task координирует операции сущностей, а правила изменения данных принадлежат соответствующим моделям. Для локальных сценариев используй `logic/tasks` владельца, для общих внутри ветки — `tasks` этой ветки.

В fullstack-версии взаимодействие с TVMaze, кеширование, фильтрация по жанрам, пагинация и избранное принадлежат backend. Frontend отправляет параметры своему API, хранит полученные данные и подготавливает интерфейс. Этапы перехода описаны в [архитектурном документе](docs/architecture.md#границы-frontend-и-backend).

Для оформления используй CSS Modules и токены из `src/shared/styles/`. Импортируй модуль как объект классов; не добавляй строковые глобальные классы, inline-стили или CSS-in-JS. Глобальные селекторы токенов, тем и reset ограничены базовым слоем `src/shared/styles/`.

## Инструменты и проверки

Используй версии Node.js из `.nvmrc` и pnpm из `package.json`. Зависимости уже используют pnpm; сохраняй этот менеджер и его lockfile.

- `pnpm check` — Biome, лимит строк исходников и проверка типов.
- `pnpm verify` — Biome, лимит строк и сборка с проверкой типов; выполняй после изменений исходников или конфигурации сборки.
- `pnpm lint:fix` — исправления Biome; для точечных правок можно передать пути: `pnpm exec biome check --write <пути>`.

Автоформатирование Markdown отключено, чтобы команды исправления кода не переписывали документацию. Для изменений только Markdown достаточно проверить содержание и ссылки.

Тестовый раннер пока не настроен. Проверка строк не проверяет границы View/Presenter и дерево владения — оценивай их по архитектурному документу. В результате работы указывай выполненные проверки и оставшиеся ограничения.
