# Доработка компонента

Прочитай [архитектуру](../../../docs/architecture.md) и [инструкции проекта](../../../AGENTS.md). Правила берутся из этих файлов; сам документ архитектуры не изменяй при реализации фичи.

При изменении интерфейса прочитай относящиеся к задаче разделы [дизайн-спецификации](../../../docs/design.md). Если задача задана номером PR, сверь его объём и критерии в [бэклоге](../../../backlog.md).

1. Найди компонент-владелец сценария и его потребителей. Для существующей фичи продолжай её ветку; для нового компонента сначала выбери владельца.
2. Раздели изменение на отображение и поведение. Во View остаются собственный Presenter и JSX. Пропсы только для отображения можно использовать непосредственно в JSX; необходимые для вычислений передавай в Presenter.
3. Собери данные, обработчики и инфраструктуру в `use<ИмяКомпонента>Presenter`, даже если хуки React пока не нужны. Вызывай Presenter на верхнем уровне View без условий и циклов. Чистые вычисления выноси в обычные вспомогательные функции; React-хуки добавляй по потребности сценария.
4. У каждой View — папка и файл с именем компонента в PascalCase, рядом — именованный Presenter. При декомпозиции сохрани эту пару для дочерних компонентов.
5. Компонент одного родителя вложи в его папку. При нескольких потребителях используй `components` ближайшего общего владельца; `src/shared/components` предназначен для разных страниц или независимых фич.
6. Соблюди лимит 120 строк исходного файла, включая JSX. Разбивай по ответственности; не скрывай превышение уплотнением кода.

Для оформления используй только CSS Modules и существующие токены из `src/shared/styles/`. Файл стилей компонента именуй точно как компонент в PascalCase: `ShowCard.module.css`, рядом с `ShowCard.tsx`. Импортируй модуль как объект классов; в JSX используй `className={styles.name}`. Сочетание статических классов можно задавать через `composes`. Не добавляй строковые глобальные классы, inline-стили или CSS-in-JS.

Общие токены, темы, reset и базовая типографика тоже хранятся в `.module.css` в `src/shared/styles/`. Глобальные селекторы ограничены этим базовым слоем; глобальные ID при необходимости явно оформляются через `:global(...)`.

Обычный HTML-элемент не требует React-обёртки без собственной ответственности. Если спецификация не определяет нужный параметр, проверь общий стиль и референс; согласованное уточнение сохрани в спецификации, не дублируя таблицы CSS-токенов.

Проверь изменённый сценарий, пропсы и обработчики, затем выполни `pnpm verify` из корня репозитория. Для изменений интерфейса проверь применимые состояния, клавиатурный фокус и адаптацию по спецификации; разделяй проверенные сценарии и ограничения. Кратко укажи, что изменилось, почему выбран этот владелец и какие проверки выполнены. Новые возможности приложения добавляй в пределах пользовательского запроса.
